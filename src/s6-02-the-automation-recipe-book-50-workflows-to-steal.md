# 6.2 The automation recipe book: 50 workflows to steal
<!-- original: ch. 52 -->

Fifty ready-to-build automations. Each one is written as trigger, steps, result. Each one works on Zapier, Make, or n8n, and many work on phone Shortcuts too.

Pick one that annoys you today. Build it this weekend. Enjoy the hours it gives back.

**How to read a recipe.** Trigger is what starts it. Steps are what happens. Result is what you get. Difficulty is Easy (under 30 minutes), Medium (about an hour), or Advanced (an afternoon).

## How to build any recipe

Every recipe follows the same six steps.

- **Step 1: Write the one-sentence recipe.** When this happens, get this, ask AI this, then do that. One sentence forces you to be clear.
- **Step 2: Build the trigger.** Start with the event that starts it. Test it with a real sample.
- **Step 3: Capture a real sample.** Use real data, not test data. Real data shows the real problems.
- **Step 4: Add one step at a time.** Test after each step. Fix what breaks before you add more.
- **Step 5: Add an approval step.** Before anything is sent to a customer, add a human yes. Keep it until the workflow has proven itself.
- **Step 6: Add the error path.** On failure, write to your Automation Log. Then publish and watch it for a week.

Use this design form for each recipe you build.

- Name: ____
- Trigger: ____
- Reads: ____
- AI step: ____
- Writes: ____
- Approval needed? yes / no
- Time saved per week: ____ minutes

> NOTE: Start with an Easy recipe that fixes a real annoyance. A recipe that saves you ten minutes a week saves over eight hours a year. Small wins compound into a system you love.

## Check yourself

- **Q1:** Which recipe step should you add before an automation sends email to customers?
**Answer:** A human approval step, such as a draft or a send-and-wait, until the workflow has proven itself reliable.

- **Q2:** What is the first thing to do when building any recipe?
**Answer:** Write the one-sentence recipe: when this happens, get this, ask AI this, then do that.

- **Q3:** Why should you test with real samples, not test data?
**Answer:** Because real data shows the real problems, such as odd formats and missing fields, that test data hides.

## In short

- Every recipe is trigger, steps, result. Once you see it, you can invent your own.
